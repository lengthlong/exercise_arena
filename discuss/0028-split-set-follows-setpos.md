## 目的

讨论 0027 的核销披露了一个遗留点：同一批录入的题录入时刻相同，并列时按 id 排，所以一个题组被题数上限切开时，先出哪几道由 id 决定，不按组内顺序 `setPos`。用户要求本轮讨论这一点。

本轮交付：裁定排序键相同时的先后规则；要改时改 `app/arena.html` 的 `dailyList` 与 `app/logic.test.js` 的断言，并重新发布页面。完成标准：断言写明新的并列规则并通过，`./check.sh` 退出码 0，线上页面换成新版本。讨论 0027 已裁的规则不变：没做过的先出，做过的按最久没用排；逐题挑选，正好取题数上限道；挑中的同组题用 `paperLayout` 在卷面上连排。

## 二、提议与裁决

### H1 排序键相同时，同组的题按什么先后排

证据：E1–E4。只改在 `lastUsed` 与 `recordedKey` 都相同之后的并列规则。

- A（推荐）**并列时先按题组排，组内按 `setPos`，最后按 id。** 同一分钟存下的几组题各自连在一起；独立的题排在这些题组之前。一组被切开时，先出的是组内最前面的几道，下一批接着出后面的。代价：同一分钟存下的几组题之间谁先谁后，由题组 id 决定，没有意义上的先后。
- B **并列时按 `setPos`，再按 id，不先按题组排。** 代价：同一分钟存下的几组题会交替排，比如先出每组的 (1)，再出每组的 (2)；切开时每组都只出一部分。
- C **保持按 id。** 代价：E3 那样，组被切开时出哪几道没有规律。

**裁决（2026-10-19）：A。**
