- E3 「最久没做」可用的数据：`dailyList` 收到的是我的视图，`attempts` 只有我的作答（`by` 为本人），每条有 `date`，新作答还有时刻 `at`。`deriveState` 推出的 `lastAttemptAt` 只看阶梯输入（每日重做的全部作答，加检验卷上做错的），检验卷上做对、部分对的作答不算进去。没做过的题只有录入日期 `createdAt` 与可省的录入时刻 `recordedAt`。

## 二、逐题

### H1 卡片底部的 Next 什么时候换成 Hand in

证据：E1。

- A（推荐）**作答阶段翻到最后一张卡，Next 换成 Hand in**，与顶上的 Hand in 同一个动作（有提醒时同样显示 Hand in anyway）。代价：还有题没答时也显示 Hand in，靠交卷前的提醒兜住。
- B **每题都有答案、又在最后一张卡时才换**，否则仍是灰的 Next。代价：没答完时最后一张卡的按钮仍点不了。
- C **每题都有答案后，每张卡的 Next 都换成 Hand in**。代价：答完后不能再用 Next 往后翻着检查。

**裁决（2026-10-18）：A。** 交卷后（对答案阶段）与 View details 的卡片底部不变。

### H2 每日卷按什么排「最久没用」

证据：E2、E3、E4。仍只取到期、未掌握的题，题组仍合成一个单元，放入与补位规则不变；只换单元的排序。

- A（推荐）**每题的键是最后一次用过的时刻，没用过就取录入时刻（`recordedAt`，没有时取 `createdAt` 当天 0 点），从早到晚排**；题组取组内最早的键排位；键相同时按录入早的在前、再按 id。一条规则同时管做过的与没做过的题。
- B **没做过的一律最前**（按录入早晚），做过的再按最后一次作答从早到晚。代价：一次录入很多新题时，久没做的旧题被挤到后面几批。

**裁决（2026-10-18）：A。** 只有日期、没有时刻的作答按当天 0 点算。

### H3 「用过」算哪些作答

证据：E3。依赖 H2。

- A **我在这道题上的全部作答**（每日卷与检验卷都算）。代价：与阶梯的口径不同。
- B **只算推阶梯的作答**：每日重做的全部作答，加检验卷上做错的，与 `lastAttemptAt` 同口径。代价：检验卷上刚做对的题，每日卷照样可能马上再出。

推荐 A。**裁决（2026-10-18）：B。**

### H4 柱上的三个数怎样显示

证据：E5。

- A（推荐）**数字写在各色段里**；有数的段至少留够写一个数字的高度，其余按比例分（柱子只大致按比例）；柱顶总数保留；部分对那段用深色字。代价：某天只有 1 次错、其余很多时，错那段比按比例的高。
- B **柱子仍严格按比例，柱顶按颜色叠三个数**（替换总数）。代价：柱顶多占约 30px，数字离色段远。

**裁决（2026-10-18）：A。**

### H5 柱上的数按作答次数还是按题数

证据：E5。复审提出（F5）：用户原话是「how many questions」，现在的柱子与柱顶总数按作答次数算。

- A（推荐）**按作答次数**，与现在的柱高、柱顶总数、悬停提示和统计行（「N answers: …」）同一单位。代价：同一题当天做两次算两次。
- B **按题数**：每天每种结果数有这种结果的题。代价：一题当天先错后对会在两段各算一次，柱子、总数与统计行都要跟着改口径。

**裁决（2026-10-18）：A。** 用户随后确认了完整核销表。
