## 一、证据

- E1 `app/arena.html` 的 `start-daily` 调用 `todayScope` → `subjectBatch` → `dailyList`。取当前用户作答推导的阶梯，限定默认归属人与按钮科目；过滤未掌握、已到期的题。生成新每日卷，今天同科目未交的旧每日卷被取代。
- E2 `lastUsed` 只看 `ladderInput`：每日重做全部作答、检验卷做错的作答；取最后时刻 `at`，缺时刻取 `date` 当天 0 点。没有这类作答时取录入时刻 `recordedAt`，缺时刻取 `createdAt` 当天 0 点。未做题没有一律优先的标记。
- E3 `dailyList` 将同一题组的到期题组成单元，取其中最早的 `lastUsed` 排单元，再按最早录入时间、最小 id 打破并列；组内按 `setPos` 排。首个单元允许超过上限，后续单元放不下会跳过，继续补位。因此它不是严格的逐题全局排序。
- E4 `todayCounts` 的按钮分数是今天每日重做过的不同题数，分母是这些题与此刻全部到期题的并集；`weekReview` 的 `questions reviewed` 是最近 7 天、全部科目与全部归属人上当前用户作答过的不同题数，包含检验卷。两者都不是英文题库的终身首次覆盖计数。
- E5 已尝试用本会话浏览器打开页面头部记载的线上网址；页面返回 `Sign in to view this page`。本会话无可用的已登录浏览器标签页，尚未取得当前数据库或线上源码。

## 二、统计口径确认

用户在本轮确认：190 来自「Last 7 days 的 answers / 柱图总数」。它是最近 7 天的作答次数，同一道题多次作答会重复计数；不是英文题库中做过的不同题数，且统计本身不限定英文。因此 `200 - 190` 不能推算当前未做题数。即使另取同范围的不同题数，也不能从其数量推导下一批必须全是未做题，因为选题没有此约束。
