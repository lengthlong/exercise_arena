### D1 新页面叫什么、放在哪

证据：E4。整个应用叫 Exercise Arena，再叫一个页面「Arena」会混。

- A（推荐）**顶上加一个标签「Games」，放在 Papers 与 Settings 之间。** 应用仍叫 Exercise Arena。代价：用户原话里的「Arena」不用作页面名。
- B **标签叫「Arena」。** 代价：「Exercise Arena」与「Arena」两个词指不同的东西，术语表要写清；对话里说「Arena」时会分不清。
- C **标签叫「Playground」或「Game zone」。** 代价：比「Games」长，手机上标签栏更挤。

**裁决（2026-10-16）：A。**

### D2 对手要不要同时在线

证据：E1、E5。

- A（推荐）**不用。一个人开一场比赛、选好对手，对手按自己的金币由电脑代跑；结果马上算出、播动画、存下来，对手下次打开能看到。** 像赛马投注街机那样，不靠几个人同时在线。代价：对手没有亲手参与。
- B **要。几个人同时开着页面，进同一个房间，各自操作自己的角色**（用 `room`）。代价：要约好时间同时在线；要声明 `room` 并实测延迟；断线、有人中途离开都要处理，做起来最多。
- C **两种都有：默认 A；对手正好在线时可以一起实时玩。** 代价：两套流程都要做。

**裁决（2026-10-16）：A。**

### D3 金币是「实力」还是「花掉」

证据：E3。金币由最近 7 天的作答滚动算出，每天都在变。

- A **实力：金币不会花掉，直接换成游戏里的能力**（举重的力气、赛跑的速度）。代价：玩家没有取舍，比赛前就大致知道谁会赢。
- B（推荐）**每场的预算：每场比赛开始时，每人拿到等于自己金币数的预算，在这一场里自己决定怎样花**（例如把预算分到几次加速、几次试举）；比完不扣，下一场重新拿。代价：要为每款游戏设计「花在哪」；对手由电脑代花。
- C **真的花掉：参赛或加速要扣金币，扣掉的要存下来，余额 = 最近 7 天挣的 − 最近 7 天花的。** 代价：要多存一份花费记录；余额可能出现负数或「今天突然变少」，要另定规则；花光了就不能玩。

**裁决（2026-10-16）：B。**

### D4 金币怎样由最近 7 天的作答算出

依赖 D3（已裁：每场预算等于金币数，所以金币的绝对数决定实力）。

证据：E2、E3。按 E3 的派生，2026-10-16 读线上数据算得的最近 7 天（实测）：

| 用户 | 作答 | 对 | 部分对 | 阶梯升到 2 级 | 升到 3、4 级 | 新掌握 |
|---|---|---|---|---|---|---|
| Aaron | 100 | 73 | 4 | 52 | 0 | 0 |
| Sophia | 48 | 29 | 0 | 13 | 0 | 0 |
| 第三位 | 10 | 4 | 0 | 0 | 0 | 0 |

「最近 7 天」指今天与之前 6 天的作答（按作答的 `date`）。阶梯升级与掌握按 `deriveState` 的同一套规则，只数发生在这 7 天里的那几次。

- A（推荐）**每次作答 1 枚；做对再加 2 枚，部分对再加 1 枚；一道题在阶梯上升到第 k 级再加 k 枚；掌握一道再加 10 枚。** Sophia = 48 + 29×2 + 13×2 = 132；Aaron = 100 + 73×2 + 4 + 52×2 = 354。做得多有金币，做对、往上爬、掌握越多越值钱。代价：检验卷可以一直组、一直做，做卷也能刷作答数。
- B **只数进步：做对 1 枚、阶梯每升一级 2 枚、掌握 10 枚；作答本身与做错不给。** Sophia = 29 + 26 = 55；Aaron = 73 + 104 = 177。代价：一周只做错题的日子金币为 0，最需要鼓励的时候拿不到。
- C **只数作答：每次作答 1 枚。** Sophia 48，Aaron 100。代价：做对、掌握不加分，「做对」没有额外回报。

**裁决（2026-10-16）：B。** 只数进步：最近 7 天里每次做对 1 枚、一道题在阶梯上每升一级 2 枚、每掌握一道 10 枚；作答本身与做错不给。按 2026-10-16 的数据 Sophia 55、Aaron 177、第三位 4。

D4a（复审 F1 引出）：「做对 1 枚」算不算检验卷上的做对。检验卷可以随时再组，卷上做对不改阶梯（`ladderInput`），若算，就能反复组卷刷金币 —— 这正是选项 A 列的代价，在 B 下照样成立。

- A（推荐）**只算每日重做（含每日卷）的做对；检验卷上的做对不给。** 每日重做只列到期题，刷不了。代价：做检验卷对金币没有帮助。
- B **两种作答的做对都给。** 代价：可以反复组卷刷金币。
- C **检验卷上的做对不给，但每周前几张交卷各给固定金币。** 代价：多一条规则。

**裁决（2026-10-16）：A。** 按 2026-10-16 的数据重算（实测）：Sophia = 13 + 13×2 = 39，Aaron = 52 + 52×2 = 156，第三位 0。「升一级」与「掌握」按 `deriveState` 的同一套规则（检验卷上做错仍会让阶梯回到第 1 级），只数发生在这 7 天里的；部分对不给。

### D5 先做哪几款游戏、各自怎样用金币

依赖 D2（已裁：对手由电脑按其金币代比）、D3（已裁：每场预算等于金币数，自己决定怎样花）。证据：E5。

用户举的三款正好对应三种决定输赢的方式。下面每款写「预算花在哪」；电脑替对手花时，按固定的平均分法加一点随机。具体数值（成功率曲线等）在实现时写成纯函数与断言，不在这里定。

- A（推荐）**三款：举重、赛跑、爬梯。**
  - **举重**（取自《Hyper Sports》，按奥运规则）：每人三次试举，每次先报要举的重量，再从预算里拿出一部分当这一次的「力气」；力气相对重量越大，成功率越高。以成功举起的最重一次排名。取舍：前面花多了，后面没力气冲大重量。
  - **赛跑**（取自《Track & Field》的 100 米）：跑道分起跑、途中、冲刺三段，赛前把预算分到三段；每段速度随投入增加，但越投越不划算，另有一点随机的风。先到终点者胜。取舍：平均分还是押在某一段。
  - **爬梯**（取自蛇梯棋）：1–50 格，有梯子也有蛇，轮流掷骰；预算每 30 枚换一次「重掷」，掷出不想要的点数时可以用掉一次重掷。先到 50 格者胜。取舍：什么时候用掉重掷。
  代价：三套规则与动画都要做，页面代码增加最多。
- B **先只做举重，赛跑、爬梯以后加。** 代价：用户要的「多款游戏」先只有一款。
- C **A 的三款再加拔河**：几个人分两队，队伍预算相加，按每一拉投入多少决定绳子往哪边走。代价：现在只有 4 位用户，分队意义不大；工作量最大。

**裁决（2026-10-16）：A。** 用户原话：「A. But the games are a little bit complicated. We need to design the game and the rules in details later.」三款定为举重、赛跑、爬梯；上面写的各款花法只是方向，玩法与规则以后再详细设计。D6（玩家在一局里能做什么）属于各款的规则，随之后移。

### D7 能选谁当对手；金币悬殊怎么办

依赖 D2（已裁：对手由电脑按其金币代比）、D4（已裁：只数进步）。

证据：E2 与 D4 的算例。按 D4 的公式，2026-10-16 Aaron 177 枚、Sophia 55 枚、第三位 4 枚、第四位 0 枚。Aaron 的作答多半是测试页面时做的；长期看，家长很少做题，金币会接近 0。无论哪边多，人与人之间的金币都可能差几倍。

- A（推荐）**能选打开过练习场的任何一位别的用户，一次选一到三位；不让分，金币多就强。** 各款游戏里本来就有运气（风、骰子、成功率），金币少的人仍有机会。代价：差几倍时，少的一方大多会输。
- B **同 A 能选的人，另加电脑选手：固定几档金币（如 30、60、120），没有真人可比、或想要旗鼓相当时选。** 代价：多一个「电脑选手」的概念，积分榜要决定算不算它们。
- C **同 A 能选的人，但让分：游戏里的实力按金币的平方根算**（55 → 7.4，177 → 13.3，差距从 3.2 倍缩到 1.8 倍）。代价：「金币越多越强」变得不直观；这其实是各款规则的一部分。

**裁决（2026-10-16）：A。** 金币为 0 的人怎样参赛（例如给不给保底预算）属于各款规则，留给各款的讨论。

### D8 一场几局、怎样算分

依赖 D5（已裁：三款游戏）。这一题只定各款通用的「局、场、分」，不定每一局怎样比（那是各款的规则）。证据：E5 中《Mario Party》评论 —— 单局分值过大会显得不公平。

- A（推荐）**一场 = 选一款游戏、选对手、选局数（1、3 或 5）；每局按名次得分，得分 = 本局打败的人数**（4 人时第 1 名 3 分、第 2 名 2 分、第 3 名 1 分、最后 0 分；2 人时赢 1 分、输 0 分；并列时平分）。一场的总分最高者为本场冠军。积分榜累计每局的分。代价：人越多每局分越多，四人局的分比两人局值钱。
- B **每局只有第一名得 1 分。** 代价：第二、三名没有回报，四人局里三个人一样白比。
- C **不按局记分，只按场记名次：每场的第 1、2、3 名各记一块金、银、铜牌**，积分榜像奥运奖牌榜一样按金、银、铜的块数排。代价：多局只用来决出本场名次；两人场里「银牌」就是输。

**裁决（2026-10-16）：A。** 并列平分的算法：并列的几人平分所占几个名次的得分之和，例如 3 人局两人并列第 1，各得 (2 + 1) / 2 = 1.5 分。一场总分并列最高时，几人同为本场冠军。

### D9 积分榜与领奖台按什么时段、怎样排

依赖 D8（已裁：积分榜累计每局的分）。用户原话给了两种显示：积分榜，或冠亚季军的领奖台。

- A（推荐）**Games 页上一块积分榜：默认看本周（周一到周日，与每周目标同一种周），可切到「All time」；顶上是前三名的领奖台，下面按总分列出全部用户。** 同分同名次。代价：多一个时段切换。
- B **只看全部时间的累计。** 代价：先玩、玩得多的人一直领先，后来的人追不上。
- C **按最近 7 天，与金币同一个窗口。** 代价：每天都在变，没有「本周冠军」这样一个定格的时刻。

**裁决（2026-10-16）：A。** 问题里一并确认了 D8 补的一句：一场总分并列最高时，几人同为本场冠军（用户未提异议）。

D9a（复审 F4 引出）：一场比赛跨过周日午夜时，各局计入哪一周。例：周日 23:55 开一场 3 局，第 3 局在周一 00:02 比完。

- A（推荐）**整场计入开赛日期所在的周。** 只存一个开赛时刻。代价：周一凌晨比完的局不算本周。
- B **每局计入自己比完那天所在的周。** 代价：每局都要存比完时刻，一场的分可能拆在两周。

**裁决（2026-10-16）：A。**

### D10 存什么（`DATA.md`）

依赖 D2、D3、D8（均已裁）。证据：E3 —— 金币能从作答现算，不必存。

- A（推荐）**金币不存，按 D4 现算，写进 `DATA.md` 的「派生字段」。比赛存成 `matches/{id}`：游戏、开赛人、选手（用户 id，含开赛人）、局数、开赛时各选手的金币、每局各选手的得分、开赛时刻；每局比完就写入，中途离开的场，已比完的局照样算分。** 各款每一局的过程数据（试举重量、掷骰点数等）写成留白，由各款的讨论定。代价：存了开赛时的金币，与现算的金币可能对不上（这是有意的：记的是当时的实力）。
- B **同 A，但只在整场比完后写入；中途离开的场不存、不算分。** 代价：比到一半关掉页面，前面赢的局白赢。
- C **只存每局得分，不存开赛时的金币。** 代价：事后看比赛记录时，说不清当时为什么谁强谁弱。

**裁决（2026-10-16）：A。**

## 三、术语定稿

按 D2–D11 的裁决，加在 `CONTEXT.md` 末尾（Knowledge map 之后）：

```markdown
### Coin（金币）

一位用户由最近 7 天（今天与之前 6 天）的作答现算出的数：每日重做里每做对一次 1 枚，一道错题在这位用户的复习阶梯上每升一级 2 枚，每掌握一道 10 枚；检验卷上的做对、部分对、做错与作答本身不给。每场比赛开始时，它是这位用户在这一场里的预算，在这一场里按游戏的规则花，比完不扣。

_Avoid_: 积分、点数、代币、余额

### Game（游戏）

用户之间用金币比试的一款小游戏：举重、赛跑、爬梯。每款各有自己的规则，规定一局怎样比、预算怎样花。

_Avoid_: 玩法、项目

### Match（比赛）

一位用户开的一次比试：选一款游戏、一到三位别的用户当对手、局数（1、3 或 5）。对手不必在线，由电脑按其金币代比。一场比赛的总分最高者为本场冠军，可以并列。

_Avoid_: 对局、对战、赛事

### Round（局）

比赛中比出一次名次的一段。没有并列时，每人的得分等于本局打败的人数；有并列时，并列的几人平分所占几个名次的得分之和，例如 3 人局两人并列第 1，各得 1.5 分。

_Avoid_: 回合、轮次

### Scoreboard（积分榜）

按本周（周一到周日）或全部时间，把每位用户各局的得分加起来排出的名次，同分同名次。一场比赛的各局都计入开赛那天所在的周。

_Avoid_: 排行榜、榜单、排名表
```
