# Reader-facing documents

Apply this guidance to publications, design overviews and README files. Adapt it to the document's purpose.

## Structure

- Introduce the subject in one sentence.
- For a design overview, use Overview, Proposal, Discussion or TODO, and References. Give background, problem, requirements and goals as applicable.
- Lead the proposal with one claim and a structural or interaction diagram. Number the main mechanisms and group a large glossary by topic.
- Compare options by common dimensions and state the decision immediately after the table. Separate near-term and long-term choices where needed. Give examples for abstractions and conclusions for figures.

## Prose

Lead with meaning and put field names, parameters and detailed examples below it. Write in the reader's terms and put implementation paths, ADR IDs and code locations in references. Use parallel phrasing for parallel items. Keep a qualifier, exception or causal explanation beside the sentence it limits. Prefer responsibilities, boundaries, flows and measured numbers to internal names. In instructions, state prerequisites before actions and identify who acts. Label actual maturity briefly and put open issues in Discussion or TODO.

Keep paragraphs to one point. For instance, name the risk of duplicate tool names first, then explain platform-specific resolution in a subitem if readers need it. Put detailed rationale and field lists in the model. Preserve all conditions when editing normative guidance. Use short phrases in tables.
