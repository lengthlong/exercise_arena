# 讨论文件：少用的情形

`design-discuss` 正文里的登记表、状态头、结论落在哪，每轮都用；下面这些只在少数轮次用到。

- **范围变化与重开讨论。** 先核对已裁结论的依赖与前提，说明哪些继续有效、哪些需要重裁；保留未受影响项，只把受影响项作为新题交用户，登记表与正文同步。重开不能仅因换了讨论文件就默认全部重问；用户明确要求从头重定时照办。冻结的旧记录不修改，核对结果写在当前讨论。
- **分批落盘**须有实际理由：用户要求先交付一部分、余题受外部依赖阻塞而本批能独立成立与验证，或已裁文件是后续取证前置等。说明理由、本批交付与范围、剩余题与继续安排；本批照常走第 4–8 步，不为采用分批另加批准。状态保持 `讨论中`，状态头说明只写已落盘批次与 commit；每批的落盘记录写在「## 分批核销（第 n 批，日期）」下，整轮核销标题用「## 六、核销（日期）」。每批核销后主动回第 3 步处理余题，全部落实后再写整轮核销、改为 ✅。
- **暂停**只在用户确认核销表之前（第 1–6 步）；落盘开始后先做完。状态头写 `> 状态：**讨论中（日期）** —— 暂停于 <题，或「核销表确认」>，让位给 NNNN；基线 <本仓 commit>`；`./check.sh` 通过后本地提交这轮已有的文件，工作区只留下一轮的改动。
- **恢复**时先看基线以来落了什么（`git log <基线>..HEAD`），逐条核对登记表上的已裁项与待裁题的证据；受影响的已裁项作为新题重新交用户裁；核对结果写进讨论文件，基线更新为当前 commit。递归时逐层同样处理；新的一轮不必为被暂停的那轮做任何事。
- **中止要交接**：一轮提前停下、不再恢复时，状态头写 `⛔ 已中止（日期）`，正文列明停在哪一题、已裁结论及其前提、未裁的问题、接手方先读什么，然后冻结；提交后用 `git show HEAD:discuss/<本轮文件>` 读出前几行核对状态头。接手后按影响核对，不要求自动重问所有已裁项。中止不代表问题已解决。
- **未完成讨论按需扫**：用户要求时，逐份取状态行（`grep -m1 '^> 状态' discuss/*.md`），列出 `讨论中` 与 `待落盘` 两类，每份一两句话。
- **由发布物改设计**：`publish/` 下的中枢有涉及设计的改动时，开一轮讨论逐题裁，见 `design-publish`。
- **复审另一个 agent 的落盘**：读对方的讨论文件、核销表与实际改动（`git show`），逐条核对；结论新开一份讨论，不回改对方已冻结的文件。
