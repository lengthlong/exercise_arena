# 讨论文件：少用的情形

登记表、状态头与结论归宿见 `design-discuss` 主文件；以下仅在对应场景按需使用。

- **范围变化与重开讨论**：先核对已裁结论的依赖与前提，保留未受影响项，只把受影响项立新题交用户重裁，同步登记表与正文；不因换了讨论文件就默认全部重问（用户明确要求重定除外）。冻结旧记录不改。
- **分批落盘**：有实际理由时采用（如用户要求先交付一批、余题受外部阻塞而本批可独立验证、或已裁文件是后续取证前置）。写明分批理由、本批范围与余题安排，本批走确认、落盘与验证；分批期间状态保持 `讨论中（日期）—— 已落第 n 批 <commit>`，核销表主标题保持 `## 核销表`，单批结果记在 `## 分批核销（第 n 批，日期）` 下并主动回第 3 步推进余题；整轮全部完成后再将主表改为 `## 核销（日期）`、状态改 `✅ 已完成（日期）`。
- **暂停与恢复**：暂停仅限确认落盘前；状态头写 `> 状态：**讨论中（日期）** —— 暂停于 <位置>，让位给 NNNN；基线 <commit>`，通过 `./check.sh` 后本地提交。恢复时用 `git log <基线>..HEAD` 核对已裁项与证据，受影响项交用户重裁，更新基线。
- **中止交接**：不再恢复时改状态头为 `> 状态：**⛔ 已中止（日期）** —— <原因>`，正文列明停在何处、已裁结论及前提、未裁项与接手阅读入口，本地提交并用 `git show` 核对状态头。
- **扫未完成讨论**：用户要求时，用 `grep -m1 '^> 状态' discuss/*.md` 列出 `讨论中` 与 `待落盘` 项及一句话进展。
- **由发布物改设计**：`publish/` 中枢出现涉及设计的改动时，开讨论裁决后再落设计文件，见 `design-publish`。
- **复审他人落盘**：对照讨论登记表、`## 核销` 表保留的原计划列与 `git show` 实际提交逐项核对；结论新开讨论记录，不回改已冻结文件。
