# design-research

研究一个外部对象，写成 `research/` 下的一份笔记，供讨论消费。用户给主题即开工，不预设问题。研究结论要改变本工作区的设计时，按 `design-discuss` 开讨论；笔记不被设计文件引用（`CLAUDE.md` 守则）。本 skill 管研究文件怎么冻结与命名、怎么研究、写成什么形状。

写或复审笔记先读同版本 `design-discuss/WRITING.md` 的共守规则，再读本工作区 `design-writing`；对象事实、主 agent 判断与未核实分别写明。改写后按共守规则对照原文核对实际稿。

笔记是给人读的**现状摘要**：正文写结论，不写考古或阅读流水。文末的「来源定位」保存影响裁决的关键结论与其一手来源，覆盖概览和深挖；仓库写基线 commit 加文件／符号定位，网页写链接加抓取日期，不能核实或不能取得固定版本时写明限制。不逐句堆出处，不另建证据库，不追改冻结笔记。

一轮研究分两段：**概览** → 用户选题 → **深挖**，写进同一份笔记（第一部分「概览」，第二部分 D1、D2……）。骨架见 [NOTE-SKELETON.md](./NOTE-SKELETON.md)：通用的几节在骨架里，随设计种类变的几节在本工作区的 `.agents/skills/design-writing/RESEARCH-SECTIONS.md`，按骨架标的位置插入。给 subagent 的简报见 [BRIEF.md](./BRIEF.md)。正文按节名引用，不按节号 —— 节号随插入的节变。

## 研究文件

- **一轮研究一个文件，冻结后只增不改。** 概览与它的深挖同在一份 `research/NNNN-<topic>.md`，消费它的讨论冻结时它一并冻结；此后同一主题要新事实就新开一份，不回改旧稿 —— 新稿头部写明抓取时间与基线，并列出它推翻了旧稿的哪些断言。
- **每一份只回答「那个时点上它是什么」**，没有哪一份承担「它现在是什么」。
- **文件名是一句简短描述**：写明对象与查了什么（`0003-tmates-execution-model`），不是光写对象名。

## 概览

1. **定对象。** 从用户给的主题定位研究对象（本地仓库路径、文档、站点、作品），记下抓取日期与基线（仓库写 commit，其他写版本或「—」）。在 `research/` 里按对象名检索旧笔记，列进简报。
2. **派后台 subagent 读源。** 按 BRIEF.md 的「概览简报」派一个后台 subagent。对象由几个独立部分组成时，按部分拆开并行，每个 subagent 读不同的源。
3. **统稿。**
   - 把草稿落进新编号的研究文件。
   - 主 agent 亲写「摘要」与「提议的细题」：「同 / 异」和值得深挖的方向要用本工作区的设计判断。
   - 「摘要」里会左右本工作区裁决的结论，回源核对一次。
   - 把这些关键结论的来源定位汇入同一笔记文末，未知与版本限制照实保留。
   完成标准：第一部分每节有内容或写明「未查 / 不适用」；「摘要」在一屏以内；`RESEARCH-SECTIONS.md` 另有完成标准的，一并满足。
4. **交用户选题。** 把「摘要」和「提议的细题」的标题摆给用户，等用户挑选。

## 深挖

对用户选中的每条细题：

1. 按 BRIEF.md 的「深挖简报」派后台 subagent，一题一个。
2. 写成第二部分的 D-n，标题是细题。
3. 回写第一部分：「提议的细题」里该条标「已深挖 → D-n」；D-n 推翻的概览句子直接改成正确的写法；整段改写「摘要」，把 D-n 的结论写成一句放进去。
4. 更新文末的来源定位，标明对应结论的位置与基线；旧结论被推翻时同步其定位，不把已失效的来源当作新结论的依据。

完成标准：该细题的问题都有答案或写明查不到；「摘要」已反映 D-n。
