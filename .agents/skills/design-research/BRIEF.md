# 给后台 subagent 的研究简报

研究对象体量大或可按独立部分并行拆解时使用；小而集中的对象主 agent 可直接读源，不必强派 subagent。

## 概览简报

```markdown
你是只读研究员，为一个设计工作区调研外部对象。不改任何文件，草稿写在你最后一条消息里。

- 主题：<研究主题与要回答的核心问题>
- 对象与入口：<本地路径 / URL>（基线：<commit 或版本；无写「—」>）
- 负责范围：<整个对象 / 子部分 X>
- 相关旧笔记：<路径列表；供对照，不复述>
- 提纲与写法：先读 <工作区根>/.agents/skills/design-discuss/WRITING.md 与 <工作区根>/.agents/skills/design-writing/SKILL.md；按 <工作区根>/.agents/skills/design-research/NOTE-SKELETON.md 第一部分及 `RESEARCH-SECTIONS.md` 适用节组织（对当前对象不适用的节直接略去；「摘要」留给主 agent 统稿）。

以最一手来源为准（源码、原始文档、实测）；二手说法与一手冲突时按一手写并点明。正文写现状结论，区分对象事实、推断与未核实。

交回：
1. 各适用节的终稿级草稿。
2. 值得深挖的未决细题（开放式调研时提供，每条附一句理由）。
3. 关键结论的一手来源定位（文件/符号或链接、commit/抓取日期、未核实限制）。
```

## 深挖简报

```markdown
你是只读研究员，深挖外部对象的一个细题。不改任何文件，草稿写在你最后一条消息里。

- 细题与问题：<细题标题及 1–5 个具体问题>
- 对象与入口：<本地路径 / URL>（基线：<commit 或版本>）
- 概览笔记：<路径>（只读相关节）
- 写法：按 <工作区根>/.agents/skills/design-discuss/WRITING.md 与本工作区 `design-writing` 写现状结论，区分事实、推断与未核实。

交回：
1. 可直接落盘的 `## D-n <细题>` 草稿（按问题组织，查不到的如实写明）。
2. 概览中需修正的原句与改法。
3. 本节关键结论的一手来源定位与基线/日期。
```
