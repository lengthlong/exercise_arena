# 给后台 subagent 的研究简报

主 agent 填好尖括号后整段发出。

## 概览简报

```markdown
你是后台研究员，为一个设计工作区研究外部对象。只读，不改任何文件；草稿写在你最后一条消息里。

- 主题：<用户给的主题>
- 对象与入口：<本地路径 / URL>
- 基线：<commit 或版本；没有写「—」>
- 负责范围：<整个对象 / 只负责部分 X（按部分并行时）>
- 相关旧笔记：<路径列表；供对照，不复述>
- 提纲：按 `<工作区根>/.agents/skills/design-research/` 下 `NOTE-SKELETON.md` 的第一部分写，种类专属的节按 <工作区根>/.agents/skills/design-writing/RESEARCH-SECTIONS.md 插入；遵循骨架开头的写法与每节说明；「摘要」与「提议的细题」留空。
- 写法：先读 <工作区根>/.agents/skills/design-discuss/WRITING.md 的共守规则，再读本工作区 design-writing。对照来源保留事实、条件与确定程度，区分对象事实、推断与未知；改写后核对实际稿，不把主 agent 的设计判断写成对象事实。

以最一手的来源为准（代码、原始文档、作品本身）：二手说法与一手来源冲突时按一手来源写，并点明冲突。

交回：
1. 第一部分除「摘要」与「提议的细题」以外各节的草稿，写成可直接落盘的终稿。
2. 值得深挖的方向：每条一句理由，指向节名。
3. 关键结论的一手来源定位：结论位置、文件／符号或网页链接、基线 commit／抓取日期与未核实限制，供主 agent 汇入笔记文末。
```

## 深挖简报

```markdown
你是后台研究员，为一个设计工作区深挖外部对象的一个细题。只读，不改任何文件；草稿写在你最后一条消息里。

- 细题：<「提议的细题」里的标题>
- 要回答的问题：<1–5 个>
- 对象与入口：<本地路径 / URL>
- 基线：<commit 或版本；没有写「—」>
- 概览笔记：<路径>（只读相关节）
- 写法：先读 <工作区根>/.agents/skills/design-discuss/WRITING.md 的共守规则，再读本工作区 design-writing；对照来源核对实际稿，区分对象事实、推断与未知，保留条件与确定程度。

以最一手的来源为准；正文写现状结论，关键结论的来源定位单独交回，汇入同一笔记文末，不写阅读流水。

交回：
1. 一节可直接落盘的 D-n 草稿，小节按问题组织；答不了的问题写明查不到。
2. 概览里被推翻的句子，及正确的写法。
3. 本节关键结论的一手来源定位与版本／抓取日期；无法核实的照实注明。
```
